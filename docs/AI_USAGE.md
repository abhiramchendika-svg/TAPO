# AI usage declaration

We used AI throughout this project. This page says what it did, what we decided, and how the work was checked.

## Tools used

| Tool | Used for |
| --- | --- |
| Claude (Anthropic), via Claude Code | Writing and editing code, tests, documentation, the website, the slide deck and its export, under our direction |

## What we decided (not the AI)

- **The problem and who it's for:** people in India with several cards who don't know which one earns the most
  for a purchase ([`PROBLEM.md`](PROBLEM.md)).
- **The safety rules:** never ask for or store a full card number, CVV, PIN, OTP, bank credentials or payment
  tokens; no real payments; sample data clearly labelled; no claims of bank partnerships.
- **The tap-to-pay demo:** NFC only *triggers* a simulated checkout; it never reads a bank card or moves money.
- **Which screens to improve and how:** transaction search and filters, tap readiness on the card screen, and
  quick actions on the receipt.
- **How TAPO is presented:** the website as a product page, with the prototype's limits stated in the README,
  the slides and [`NOT_BUILT.md`](NOT_BUILT.md).
- **Hosting:** a public GitHub repository and the Vercel deployment.
- **The research:** who to interview, running the eight interviews, and recording what people said.

## What the AI produced

- Most of the TypeScript and React Native code in `src/`, and the unit and end-to-end tests.
- The public website in `site/`, including the animated tap-to-pay page.
- The README and the documents in `docs/`, the README images and the app icons.
- The slide deck in [`docs/slides`](slides), built from our direction, and its PDF export.
- The write-up of our interviews: the participant table came from us; the AI formatted it and counted the results
  for each hypothesis. **No research data was generated by AI.**

## How the work was checked

Automatically, on every push ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml)): TypeScript type
checks, ESLint, the Jest unit tests and a web export of the app. Playwright end-to-end tests (run locally) cover
the website and the web app's sign-in.

By us, before the review:

- [ ] Each of us has read [`ARCHITECTURE.md`](ARCHITECTURE.md) and can explain any core module without notes.
- [ ] We ran `npm run typecheck`, `npm run lint` and `npm test` ourselves.
- [ ] We tested the app on the phone we're bringing to the review, and in a browser.
- [ ] We tried entering a full card number in every text field, and TAPO refused it.
